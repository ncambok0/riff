# RIFF 実測・反復・自動再計画 仕様（承認方向の整理）

## 1. 基本思想
RIFFは「本人が全部の予定を管理する道具」ではなく、「本人の実行結果を使って次の計画を育てる道具」とする。
自由度は残すが、安全な範囲の更新は原則自動反映する。

## 2. タスクを4種類に分ける

### A. 学習（単元の理解・定着）
同じtask.idを3回測る方式を使わない。
単元単位の履歴をつなげる。
- ① 確認する
- ② 問題を解く
- ③ 間違い直し
- ④ 思い出す（後日）

既習単元：最初の実施を診断として扱い、1回目から時間・正答率・難易度を次の判断に使う。
未履修単元：予習の所要時間は1回目から使うが、理解度判定は授業後の問題演習から始める。
復習：結果を毎回すぐ次の復習期限・段階判断へ使う。

### B. 音楽の反復練習
対象：
- 技法練習（ミュート、チョーキング、ビブラート等）
- スケール、コードチェンジ等
- 楽曲練習・コピー練習（同じ曲／同じ区間／同じテンポ目標）

同じtask.idではなく `practiceKey` で同種練習を束ねる。
例：`song:nirvana-smells:verse-riff`, `technique:single-note-muting`
3回以上の実測で中央値を安定した目安として使う。

### C. 開発の反復ドリル
対象：
- Python文法ドリル
- リスト／辞書／関数など短い反復問題
- NumPy等の操作練習
- 同じ技能を複数問題で反復する練習

`practiceKey` 単位で3回以上の実測中央値を使う。
制作工程（MIDI実装、画面4分割等）はここに含めない。

### D. 一回性の制作・設定・実装
初回実測から類似作業の計画材料にする。
同じタスクを3回やらせない。
将来は `workType`（implementation/debug/recording/mixing/setup等）単位で傾向を学習する。

## 3. 時間反映の原則
- 「時間不足」の観測は早く反映する。初回が仮見積もりを大きく超えた場合、次回候補を拡張する。
- 「短く済んだ」は1回だけで大幅短縮しない。複数回の安定を見て縮める。
- 反復練習は3回中央値を安定値とする。
- 学習は3回待たず、単元履歴と正答率を使う。

## 4. 学習の復習管理
現行の1・4・14日は初期運用値であり、最適値とはしない。
学習完了後、RIFFが復習キューを作る。

例：
- 問題演習で誤答が多い → ③間違い直し
- 間違い直し完了 → ④短い間隔で思い出す
- 後日高正答 → 次の間隔を広げる
- 後日崩れる → 間隔短縮または③へ戻す

正答率の閾値は固定された科学的真理として扱わず、初期ルール＋実データで調整する。
本人の自己評価だけで定着判定しない。

## 5. 今日タブの表示
各学習タスクに今回の段階を必ず表示：
- ① 確認する
- ② 問題を解く
- ③ 間違い直し
- ④ 思い出す｜1日後/4日後/14日後/調整後

復習期限が来たものは今日タブで優先。
未実施なら消さず「期限超過」として残す。

## 6. 自動再計画
実測を保存したら、未来の未開始枠についてRIFFが再計算する。
原則自動反映してよいもの：
- 未開始の未来枠
- 自動提案されたタスク
- 時間不足による後送り
- 復習キューの追加

保護するもの：
- 完了済み
- 実行中
- 過去の時間枠
- 本人が固定した予定
- 明示的に手動配置した予定（固定扱いを選べる）

自動変更後に「何を変えたか」を表示し、Undoを可能にする。

## 7. 現行実装との違い
現行コードは同じtask.idの実測が3回以上で中央値を採用し、計測だけでは今日の既存予定を変更しない。
この文書は次期仕様。①実機確認が終わるまでは大規模挙動変更を実装しない。

## 8. 保存モデル案
```json
{
  "practiceKey": "song:...",
  "workType": "practice|drill|implementation|debug|recording|study",
  "learningStage": "check|solve|correct|recall",
  "unitId": "...",
  "attempted": 10,
  "correct": 8,
  "difficulty": 3,
  "actualMinutes": 18,
  "completedAt": "...",
  "nextReviewAt": null
}
```
既存の `riff_task_sessions_v1` は削除せず、移行時は読み取り互換を維持する。

## 9. 判定に必要な入力と入力不足の扱い
- 学習の初回評価は短い確認問題を基本とする。本人の主観難易度だけを習得判定に用いない。
- 問題数・正答数を登録したときのみ正答率を計算し、未入力なら「習得度未判定」として短期の再確認を提案する。
- 答えやヒントを見て正解した場合は自力正解として扱わない。将来の記録には `assistanceLevel`（なし／ヒント／解説を参照）を追加する。
- 難易度・正答率・所要時間・前回間隔・実際の教材の版／設問を履歴と結び付ける。異なる教材の難易度を補正なしで比較しない。
- 明確な正答率の閾値は実装前に仮値として定義し、利用中の実績に基づき改訂可能にする。難易度が高い場合は正答率が高くても早めの再確認を提案する。

## 10. 復習キューの状態遷移
状態：`not_started` → `check` → `solve` → `correct`（誤答がある場合）→ `recall_due` → `recall_done` → `mastery_observed`。
- 既習単元は `check` で診断を実施し、十分なら未履修向けの導入説明を省略できる。
- 未履修単元は学校での実施確認まで診断結果を「理解不足」として評価しない。
- 複数日の想起テストで定着を観測する。1回の高得点では恒久的に復習を打ち切らない。
- 1・4・14日は最初の仮間隔であり、不正解なら解き直しへ戻すか次の間隔を短縮する。
- 期限日とタスクIDを保存し、端末の表示日が変わっても期限超過の課題は消さない。
- 日次上限を超える復習が溜まった場合は、期限超過・学習上の重要度・必要時間から候補順位を計算し、残った分も翌日以降に持ち越す。

## 11. 安全な自動再計画・競合処理
- 記録確定の時点で新しい時間見積もりと復習キューを作る。今日の未開始かつ自動配置の枠だけを再計画の対象にする。
- すでに開始した枠、終了済みの枠、本人がピン留めした枠、本人が手動で入れ替えたタスクは保護する。
- 枠超過のときは学習／復習の必要性を消すのではなく、今日から外れたタスクを翌日以降の未配置キューに保持する。
- 時間割の変更・タスクの完了・追加・手動変更・別端末の同期が再計画前に起きたら、古い計算結果を適用せず最新状態から再計算する。
- 自動変更には変更前と変更後、時刻、理由を記録し、取り消しを可能にする。ただし取り消しても実測履歴や復習必要性は削除しない。
- 生活時間・睡眠・学校の予定に自動割込しない。今日の余剰がない場合は「未配置」として通知する。
- 保存済み履歴には偽の成功結果・架空の実施日・推定得点を記入しない。
- ①実機確認の間は仕様のみ。自動再計画を現行アプリに突然有効化しない。

## 12. 最低限のテストケース
1. 初回実測が見積もり超過 → 次の未開始の自動枠だけ調整
2. 初回実測が短い → 大幅な見積もり短縮を保留
3. 同じ楽曲の同じ区間を3回練習 → `practiceKey` による中央値
4. 異なる曲の練習 → 勝手に同じ反復母集団へ統合しない
5. Pythonドリル3回とゲーム実装1回 → 反復／一回性を分ける
6. 学習で誤答あり → 間違い直しと再確認を作成
7. 復習が期限超過 → 未完了のまま翌日も表示
8. 学習記録の問題数が未入力 → 定着判定を捏造しない
9. 保存済みの手動タスクと現在実行中の枠は自動変更しない
10. 古い再計画結果を最新の時間割に適用しない
